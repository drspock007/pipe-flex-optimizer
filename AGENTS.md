- Ground searches (Find h, Find L) share one adaptive sampler (mechanics-v2/ground-sampler.ts) and one solve classifier (ground-classify.ts); Find L samples ln L. Why: identical exploratory guarantees, one place to fix.
- Ground fixed-L solve tries the exact no-ground solution first (ground-fast.ts), accepted only if exact member minima clear the ground by > tolPenetration; else the mesh path, which stops after 2 consecutive precision-loss levels. Why: round-off in K d - F grows ~N^3, so ground-inactive cases must not be meshed.
- Min. supports with ground (ground-min-search.ts) runs Find L with ground for n = 0..ceiling in order under ONE global budget, with an independent final check; only n = 0 is certified minimal. Why: support positions change with n (no bisection), exploratory searches never prove impossibility.
- The V2 hook keeps one worker per channel and terminates a busy one on a new request; progress messages go through the channel reducer (stale ids ignored). Why: obsolete searches must not consume their budget.
- Axial mode "restrained" (Fixed L, Find h) has its own solver (restrained-*.ts): Hermite + exact geometric matrix, N found by the monotone dual compatibility equation, never the free-mode exact/ground-fast paths. Why: those closed forms assume N = 0.
- Restrained Find h (restrained-height-search.ts) reuses ground-sampler.ts with its own necessary axial bound hv^2 + hl^2 <= 2L^2 sA/E (never the free Hcap) and classifies on the combined criterion; Find L / Min. supports stay unavailable in restrained. Why: Hcap is derived for N = 0 only.
